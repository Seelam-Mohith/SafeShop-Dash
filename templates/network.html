Documentation only. This dashboard does not read live Wireshark captures, talk to tshark, or ingest pcap files. The notes below are static laboratory reference material for correlating the JSONL access logs with packet-level observations captured manually in Wireshark.

Capturing loopback traffic in Wireshark

  1. Install Wireshark (with the Npcap loopback adapter on Windows) and select the Loopback interface (\Device\NPF_Loopback / “Adapter for loopback traffic capture”).
  2. Apply a capture filter: tcp port 5000 for the legitimate site or tcp port 5001 for the compromised simulation.
  3. Start the relevant Flask application and generate traffic, either manually in a browser or with the laboratory traffic generator: python tests/generate_test_traffic.py all (run from SafeShop-Compromised).
  4. Stop the capture and correlate HTTP request/response pairs with the corresponding JSONL log records (same timestamp, path, and status code).

Expected packet-level evidence per scenario

Scenario / rule Capture filter Expected HTTP evidence Log correlation
A — Unexpected redirect
WHD-001		 tcp port 5001 GET /lab-test/redirect answered by HTTP/1.1 302 Found with a Location: /lab-test/redirect-target header Log record with path=/lab-test/redirect and status_code=302
B — Suspicious path
WHD-002		 tcp port 5001 GET /lab-test/admin-test answered by HTTP/1.1 200 OK (static lab page) Log record with path=/lab-test/admin-test
C — Abnormal method
WHD-003		 tcp port 5001 POST /lab-test/method-check answered by HTTP/1.1 405 Method Not Allowed Log record with method=POST and status_code=405
D — Repeated requests
WHD-004		 tcp port 5001 Burst of GET /lab-test/repeat requests within a short window Many log records for the same path in a 10-second window
E — Unapproved resource
WHD-005		 tcp port 5001 GET /lab-test/resources/unapproved.js served from the same origin (path-level indicator only — not proof of a cross-origin load) Log record with the unapproved resource path

Correlation workflow

  1. Run the detection engine (dashboard Analyze Logs button or python detector.py).
  2. Open the Alerts page and note the timestamp, path, and status of an alert.
  3. In Wireshark, display-filter by request line, e.g. http.request.uri == "/lab-test/redirect".
  4. Confirm the packet-level response matches the logged status code and any redirect headers.

Scope & limitations

  • No live packet capture integration exists; all evidence on this page is reference documentation.
  • Loopback captures require the Npcap loopback adapter; redirects are only visible at packet level when capturing on the loopback interface.
  • Scenario E is a path-level indicator: the unapproved script is served by the same application origin.
  • Detection figures shown elsewhere in this dashboard come exclusively from the JSONL access logs, not from packet data.
